Actions

Lancer le plan (synchro) déclenche immédiatement un cycle de snapshot/restauration pour toutes les VMs sélectionnées, comme le ferait le job planifié. Activer/Désactiver et Supprimer sont réservés aux admins.

Bascule PRA

Activation PRA (réservée aux admins) démarre les VM cible dans l'ordre configuré (page Modifier), réutilise les EIP de production et reconstruit la NAT Gateway avec l'ancienne IP publique (ou une nouvelle si ça échoue) — action réelle et irréversible, le plan est ensuite désactivé automatiquement. Test de PRA fait la même chose mais avec des EIP et une NAT neuves, sans jamais toucher à la production ; la sync planifiée est suspendue tant que le test tourne, à terminer explicitement via Terminer le test (redémonte tout, reprend la sync).

Sandbox

Créer un sandbox clone un VPC indépendant du VPC de PRA et le construit comme un Test de PRA — pour expérimenter sans jamais toucher au VPC de PRA officiel. Géré depuis le menu Sandbox.

Ressources PRA

Compare les ressources réseau du VPC source et du VPC cible (subnets, security groups, route tables...) — un ⚠ Écart détecté signale des objets manquants côté cible. Le scan du VPC source se rafraîchit automatiquement toutes les heures, ou à la demande via Rescanner le VPC source. Mettre à jour depuis la source recrée les objets manquants côté cible (subnets, security groups + règles, internet service, tables de routage — hors routes vers un Net peering/VPN, EIP et NAT Gateway, repris seulement à la bascule).

VMs et points de sauvegarde

Pour chaque VM : nombre de snapshots disponibles, date du dernier snapshot, date du snapshot restauré sur la VM cible, et statut — Défaillant si le dernier job de cette VM est en erreur.

Journal des exécutions

Historique des jobs de ce plan (un par VM et par cycle). Le bouton Voir affiche le détail pas-à-pas dans le panneau Journal.
